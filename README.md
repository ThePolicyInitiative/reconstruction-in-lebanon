# Reconstruction in Lebanon

A Streamlit website. Its first tab, **Government response**, is a compact one-page infographic: initial funding and its allocation, nine named officials with concise roles, and a three-step reconstruction path. Sources, scope notes and the full research data are available in a collapsed panel. The white page adapts to desktop and mobile.

The other top-level tabs are, in order:

2. **Budget** — the supplied `war_achraf(Sheet1).csv`, comparing the 2026 law with both 2027 drafts. Shows reported totals, selectable activity breakdowns, changes between drafts, all line items and beneficiaries, and the original download. Totals count the 15 level-5 rows once; four family-support components are preserved separately. Unavailable amounts remain `n.a.`. Arabic labels were already replaced with question marks in the source, so the page uses its English descriptions.
3. **Restrictions & funding gaps** — bilingual one-page overview with a LEAP funding strip and two case panels. Select a restriction or local funding gap to see its town, date, authority, affected activity and known amounts together. Context, sources, the full financing chart and state-budget history open in popovers.
4. **Tenders** — Mona2asat's PPA and CDR dashboard, limited to announcements dated in 2024, 2025 and 2026, with search, filters, district charts, seven overlapping categories (LEAP, Reconstruction, Damage assessment, Roads, Electricity / water, Shelter management, Debris removal), source documents and CSV/JSON downloads. Checks the cloud monitor's saved results every 60 seconds while this tab is open. Uses current cloud archives, including records collected while this computer was off; local direct collection every 30 minutes supplies a backup when cloud data is over 36 hours old. Counts remain separate because the two sources can overlap.
5. **Gazette** — Saved Lebanese Official Gazette records from Memo automation, covering 2024–2026, immediately beside Tenders. Search Arabic titles or document numbers; filter by year, document type, original policy category, review status and the same seven website subjects as Tenders. Seven interactive charts show subjects by year and document type, monthly activity, annual comparisons, document nature, policy areas and classification review status, with counts, percentages and detailed tooltips in English and Arabic. Annual comparisons default to the same calendar cutoff; missing source months remain unavailable rather than zero. Original-record links and CSV/JSON downloads retain source classifications.
6. **What parties are saying** — two interactive X/Y graphs, each on its own full-width row, with reconstruction on the horizontal axis and arms or financing on the vertical axis. Switch between 79 parties and political movements (inside and outside Parliament), all 128 MPs, and the 24-member cabinet. Photos and emblems remain the plotted points, with the full name and both evidence-coded position summaries beside each. The SVG layout packs text into available neighbouring space while preserving the marker’s exact reconstruction category and arms/financing band. Names and summaries wrap without truncation; image, connector and text boxes are checked for overlaps. Full speakers, statement context and dated sources remain in the selected-point evidence panel. The graphs distinguish 9 reconstruction approaches, 8 arms positions and 10 financing approaches, with short bilingual axis labels and full definitions in an expandable guide. Empty cells have no count strip; row heights follow their contents. Desktop graphs fit the available width. The full comparison uses a 900px minimum canvas on narrow screens; choosing one reconstruction column fits the narrower viewport. Coverage totals, distributions, exact figures and CSV exports always retain the full layer. Missing personal positions stay unassigned and never inherit a party or cabinet position. The full directory and previous statement archive remain accessible below the graphs.
7. **What countries are saying** — 20 countries and 30 dated statements, with country and official filters, timelines, original sources, and distinctions between reconstruction, recovery services, humanitarian assistance and political support. The original page came from `http://127.0.0.1:8787/?view=countries`; it works without that server running. Nine additional countries and 12 official-source records are maintained in `data/country_additions.json`, reviewed on 12 October 2026. These records survive an intentional source refresh with `python -m scripts.import_countries_page`. After editing the additions, run `python -m scripts.country_content`, review Arabic translations, and run `python -m scripts.install_localization`. Provenance is in `imported/countries/provenance.json`.
8. **Evidence of destruction** — the existing satellite comparisons, image viewer, access to annotated originals from the 2006 section, damage assessments and linked local reports. The gallery has its own keyboard, mouse and touch scroll area, with an image viewer that stays within the screen.

The imported pages live in `imported/` and the tender dashboard in `integrated_tenders/`. They run inside this Streamlit application, with no second server or access to the original project folders required. Imported HTML pages use Streamlit's local component server so their images, internal navigation and report links work. The original source projects are untouched. `imported/manifest.json` records provenance. The tender integration is maintained separately from the initial import script, which now preserves its live connection.

### Automatic tender collection

`run_website.py` starts one background collector thread before launching Streamlit, so checks run even before a browser connects. The standard `streamlit run streamlit_app.py` command also starts the same monitor on the first website session. `integrated_tenders/automatic.py` keeps collecting while the server process is running, even if the browser closes or another tab is selected. It checks both sources every 30 minutes, retries failed scans and incomplete details after five minutes, and resumes overdue scans after a restart. A sleeping computer or stopped/hibernated hosting service cannot run checks. No OS scheduled task, GitHub workflow, billing setting, or notification service is changed.

The collectors in `integrated_tenders/collectors/` are vendored from Mona2asat, with provenance and hashes in `provenance.json`. They retain full pagination validation, pending detail retries, and daily ongoing-lot refreshes for CDR. PPA details remain first-discovery snapshots. The notification module is not included or executed. `lxml` is required for HTML parsing.

`.cache/tender-monitor/working/` contains mutable collector state. An OS file lock prevents overlapping scans, including across Streamlit reruns or multiple processes. Content-addressed immutable objects and an atomic current-snapshot pointer keep each source's table, full records and downloads consistent. Successful sources publish independently; failures preserve that source's last published records and timestamp. `worker-state.json` records actual checks, errors, next due times and a worker heartbeat. Do not manually advance timestamps. Fresh installations rebuild collector state from the packaged full records.

The original GitHub Actions monitor runs on GitHub's servers, independently of this computer. It has an active scheduled workflow in `ThePolicyInitiative/mona2asat`; no new hosting account is required. Cloud operation was verified as restored on 19 October 2026: user-started run https://github.com/ThePolicyInitiative/mona2asat/actions/runs/39229705966 completed successfully and published fresh PPA and CDR data. The earlier billing/spending restriction no longer prevented that run. The repository owner is the personal GitHub account `ThePolicyInitiative` (verified through repository metadata). The workflow, billing settings, repository visibility and alert configuration have not been changed by this website update.

## Run

Use Python 3.12, install `requirements.txt`, then run:

```sh
python -m pip install -r requirements.txt
python run_website.py
```

On this Windows workspace the local environment is already set up:

```powershell
.\.venv\Scripts\python.exe run_website.py
```

## Deployment

The app is prepared for Streamlit Community Cloud with entry point `streamlit_app.py` and dependencies in `requirements.txt`. Direct tender collection and the other tabs need no credentials. Optional GitHub fallback needs repository read access as described above. Automatic checks require a running server with outbound access to PPA/CDR and writable cache storage; a hosted service may sleep when unused. The repository contains the website source and bundled assets. Uploading this repository does not deploy a live Streamlit website. When hosting, configure repository/Memo access through environment variables or Streamlit secrets; local Windows credentials are not included.

- Tender categories are recalculated locally by `integrated_tenders/categories.py` from notice titles, summaries and saved source-text evidence. The original Mona2asat feed is unchanged. Buyer names, explicit exclusions and unrelated household-waste or shelter references are screened to avoid false matches. Each tender can match several categories; the matched wording remains inspectable. Arabic labels retain canonical English filter values.

## Gazette cloud connection

`integrated_gazette/live_data.py` reads the existing private Memo automation Site directly. It checks the small `/api/pipeline?action=status` response once per minute while the Gazette tab is open, downloads `/api/data` only when the revision changes, verifies the full record count and the exact owner-workbook classification fields, and replaces the cache atomically. A concurrent pipeline change requires matching readback; a failed or invalid response keeps the last good data and retries after one minute. Every request is GET-only, fixed to the Memo Site origin, and redirects are rejected so the credential cannot be forwarded elsewhere.

Memo automation's existing cloud schedule remains active every Monday at 09:00 Asia/Beirut. It collects and classifies newly published Gazette records without this computer. The website reconnects on opening, so there is no manual export step. The local Streamlit website itself still needs this computer running; cloud collection does not host the local website.

Service access is read from `GAZETTE_SITE_TOKEN` in hosting environment/Streamlit secrets, or from a dedicated Windows Credential Manager entry on this computer. The one-time `python -m scripts.connect_gazette_cloud` setup receives the existing Site service credential through hidden stdin, validates a live read, and stores it using the Windows user credential API. Tokens are never included in source, command arguments, logs, snapshots, URLs, browser code or schedule prompts. Site privacy, Gazette subscription credentials and cloud schedules are unchanged. If the Site service credential is later rotated, reconnect with its replacement; the website reports authentication failures without discarding saved records.

`.cache/gazette/cloud.json` holds the last verified full cloud dataset and `connection.json` holds non-secret connection metadata. The website continues to show 2024–2026 only. The packaged export and optional local Memo export are emergency fallbacks before any cloud cache is available. Once cloud data is available, it is authoritative; local files cannot overwrite it. The seven website subjects remain separate title filters and never change original classifications. CSV/JSON downloads preserve the original named labels and deliberate blanks.
